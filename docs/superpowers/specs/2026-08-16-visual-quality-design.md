# 見た目の完成度を上げる 設計

## 1. 何が問題か

この作業期間に出た品質の指摘9件は、すべて利用者が見つけた。開発側は1件も先に
見つけていない。試験は209件通り、型検査もビルドも通っている。

| 指摘 | 実際の原因 | 層 |
|---|---|---|
| 牌が文字ラベル | 牌面を持っていなかった | 素材 |
| 牌がほぼ全部別の牌に化ける | アトラスの行が上下反転 | 素材 |
| 牌面が焼けない | SVG に `xmlns` が無い | 素材 |
| 取ってつけたような3D | 面取りの無い直方体、厚みが実物の 0.75 倍 | 造形 |
| 白に違和感 | 細い長方形1本で、枠に見えない | 素材 |
| 解像度が低い | 牌面1枚が 128px、異方性フィルタ無効 | 造形 |
| 手牌が読めない | 俯瞰カメラに対して牌を立てていた | 情報 |
| 捨て牌が分からない | 直前の捨て牌を画面に出していなかった | 情報 |
| ボタンが押せない | 毎フレーム DOM を作り直していた | 操作 |

**「絵を誰も見ていない」とまでは言えない。**次の構造的な防御は既にある。

- `face-atlas.test.ts` は全セルの `xmlns` を検査する（「3Dだけ読めない」事故の回帰防御）
- `atlas.test.ts` はセルの行と canvas の行の向きを検査する（上下反転の回帰防御）
- `tile-face.test.ts` は37種の図柄数・字牌・赤ドラの構造を検査する
- `preview.html` は副露5種・リーチ・長い河を決め打ちで出す

**足りないのは「最終的な画素を誰も見ていない」ことである。**構造は守られているが、
出来上がった絵が正しいか、綺麗かは検査されていない。

**そして画素比較でも防げないものがある。**「ボタンが押せない」「何が起きたか
分からない」は、絵としては正しく写る。**画素比較を入れれば9件すべて防げる、
という話ではない。**操作と情報の層には別の手当てが要る。

## 2. 順序

**利用者は4つの層すべてを不満として挙げた。**素材だけ直しても、押せない・
分からないは残る。したがって次の順で進める。

| 順 | 層 | 中身 |
|---|---|---|
| 1 | 操作・情報 | 残っている「使えない」を潰す |
| 2 | 素材 | 牌面を本物の牌図へ |
| 3 | 造形 | 光と質感 |
| 4 | 手応え | 音・強調（このウェーブでは扱わない） |

当初は「土台が汚いまま手応えを足しても効かない」として素材を先に置いたが、
**タスクを達成できない障害を後回しにする理由にはならない。**

第1層で扱うのは、既に直したもの（押せないボタン、直前の捨て牌の表示）に加えて、
**残っている操作・情報の障害の洗い出しと修正**である。洗い出しは実際に半荘を
通して行い、見つかったものを一覧にしてから直す。

## 3. 素材

### 出所と許諾

**Wikimedia Commons の Shizhao 氏による Unicode 系統一式のみを使う。**

- 命名: `U+1F000`〜`U+1F021` に対応する `U+1Fxxx_MJ*.svg`
  （例: `U+1F002_MJWestwind.svg`、`U+1F007_MJ1wan.svg`）
- 作者: Shizhao
- 許諾: **CC0 1.0（パブリックドメインへの献呈）**
- 寸法: 75 x 95 px。**34種すべてが同じ寸法である**

| Unicode | 種類 |
|---|---|
| U+1F000〜U+1F003 | 東南西北 |
| U+1F004〜U+1F006 | 中發白 |
| U+1F007〜U+1F00F | 一萬〜九萬 |
| U+1F010〜U+1F018 | 一索〜九索 |
| U+1F019〜U+1F021 | 一筒〜九筒 |

**`0401東風.svg` のような別系統を混ぜてはならない。**当初この設計はそれらを
含めていたが、作者は碧海风、許諾は **CC BY-SA 4.0**、寸法は 140 x 200 であり、
パブリックドメインではなく、寸法も揃わない。表示義務と継承義務が生じる。

### 取り込みの手順（この誤りを二度と起こさないため）

取り込みは手作業で行わない。**次を機械的に行う取り込み用のスクリプトを書く。**

1. Commons の API で対象ファイルの情報を引く
2. **各ファイルの許諾を検査し、CC0 か PD でなければ中断する**
3. 寸法が 75 x 95 でなければ中断する
4. `apps/web/src/assets/tiles/` へ保存する
5. `CREDITS.md` へ、ファイル名・作者・許諾・寸法・取得元 URL・取得日を書く

**許諾の検査を人の目に任せない。**今回の誤りは、系統の違うファイルを一括で
「パブリックドメイン」と書いたことで起きた。

### 赤ドラ

**色の一括置換はしない。**SVG には複数の `fill`/`stroke`、埋め込みの style、
グラデーションがあり得る。中身を確かめずに置換すると、背景や輪郭まで赤くなるか、
あるいは何も変わらない。

取り込んだ五萬・五筒・五索の**3ファイルの中身を実際に読み**、色を持つ要素を
特定したうえで、ファイルごとの置換規則を書く。置換の結果は牌姿一覧で確かめる。

### 2D と 3D の一致

現在 `face-atlas.ts` は「**牌の面は `ui/tile-face.ts` が唯一の定義である**」と
明記している。外部素材を 3D にだけ使うと、この単一の定義が壊れ、鳴きのボタン
（2D）と卓の牌（3D）で白や一索の見た目が食い違う。

したがって**2D も同じ素材を使う。**`tile-face.ts` の自前描画は残さず、取り込んだ
SVG を返す形へ差し替える。控えとしての二重定義は持たない。

## 4. 造形

### 彫りの表現

**方向のある陰影を焼き込まない。**焼き込むと光の向きが固定され、牌が席ごとに
90度回るため、模様の中の光だけが一緒に回って立体の陰影と矛盾する。

代わりに、**図の周囲に等方の暗い縁**（内側へ均一に落ちる影）だけを入れる。
向きを持たないので回転しても破綻しない。加工は取り込み時にラスタライズしてから
アルファの境界に対して行う。

**これは素材現物で試作してから採否を決める。**効果が薄ければ入れない。

### 光

環境光と平行光の2灯に**半球光**を足し、上からの明かりと卓面からの照り返しを
分ける。牌の面取りが光を拾い、輪郭が出る。

**既存の2灯を再調整する。**足すだけでは明るさが飽和する。調整後の見え方は
牌姿一覧と盤面の見本で確認する。

### 質感

面と側面で粗さを変えるのは、いまの単一マテリアルでは素直に書けない
（面別のグループが無く、UV のセルで分けているだけ）。**このウェーブでは行わない。**
粗さマップを足すか面別グループを作るかの判断が要り、費用に見合わない。

### 接地の影

**このウェーブでは行わない。**牌ごとに透明な板を足すと、重なり順・深度・卓面との
干渉でちらつく危険があり、描画量も増える。半球光による輪郭の改善を先に見て、
それでも浮いて見えるなら別途扱う。

（当初は「最も削りやすい項目」としながら受け入れ基準に入れていた。矛盾である。）

## 5. 見本比較の仕組み

### 二段構えにする

**一つの閾値で両方は測れない。**全画面の差分率だけで見ると、環境差で全画素が
1階調ずれれば常に落ち、逆に牌1枚が別牌に化けても面積が小さく見逃す。

| 対象 | 撮り方 | 判定 |
|---|---|---|
| **牌姿一覧**（37種＋裏） | **WebGL を使わず**、アトラスを 2D で描いて書き出す | セルごとに厳しく比較。牌の化けはここで必ず出る |
| **盤面**（3D） | ヘッドレスで撮る | 画素ごとの色差に許容を置き、**差の出た画素の割合**で判定 |

牌姿一覧を WebGL から切り離すのが要点である。**牌の化けという最も痛い事故は、
3D を経由せずに検出できる。**

### 撮影経路の代替

現在ヘッドレス Chrome が本プロジェクトの 3D ページで画像を書き出さない。
`about:blank`・WebGL を使わないページ・最小の WebGL ページはいずれも撮れるので、
Chrome 自体ではなく本プロジェクトの場面に固有の問題である。

**3D の撮影が直らなくても、牌姿一覧の検査は成立する。**加えて次の代替がある。

- Playwright で Chromium と起動引数を固定する
- Vitest のブラウザモードを使う
- 描画ループを止めて1コマだけ描く口を `preview.html` に設ける

**依存を一本にしない。**「直らなければ設計を見直す」で済ませない。

### 見本の置き場

承認済みの見本だけを **PNG で少数** リポジトリへ置く。差分画像はリポジトリへ
入れない。**PNG は差分が読めないので、枚数を増やすと履歴が膨らむ。**
viewport・OS・席・状態を掛け合わせて増やさない。

**見本の更新は人間が承認する。**新しい見本が良いか悪いかは機械には決められない。

## 6. やらないこと

- 音、キャラ立ち絵、カットイン、和了のカメラワーク
- 卓の木目や布地の作り込み
- 山のバッチ化などの描画性能の作業
- 牌の粗さの塗り分け、接地の影（第4節のとおり）

## 7. 受け入れの基準

- **操作・情報**: 半荘を通して洗い出した障害の一覧があり、そのすべてが直っているか、
  直さない理由が書かれている
- **素材**: 37種すべてが取り込んだ牌図で描かれ、`CREDITS.md` に全ファイルの
  作者・許諾・寸法・取得元が記録されている。**CC0 か PD 以外が1件も無い**
- **一致**: 2D の盤面と 3D の卓で、同じ牌が同じ絵で描かれている
- **造形**: 半球光を入れた状態の牌姿一覧と盤面が見本として承認されている
- **検査**: 牌姿一覧の比較が WebGL 抜きで動き、牌を1種入れ替える変異で落ちる
- 既存の 209 件の試験が通り続ける

**「綺麗になったか」は人間が決める。**機械が決めるのは「承認された状態から
崩れていないか」だけである。
