# 人と打てる卓 —— 部屋・席・トークン 設計仕様書

作成日: 2026-08-30
位置づけ: 全体設計 `2026-08-08-real-mahjong-design.md` の第2段（運用機能）の1枚目。
同 8.1 が予告していた「署名付きの再開トークン」をここで入れる。

---

## 1. 何を作るか

**人が2人以上、同じ卓に座れるようにする。** いまは席0が人、1〜3が CPU で固定されている。
友人にコードを渡せば同じ卓に着き、空いた席は CPU が埋める、という状態まで持っていく。

同時に、いま開いている穴を塞ぐ。`matchmaking.rs` と `serve.rs` の冒頭には
こう書いてある。

> **このウェーブに認証は無い。** id を知っていれば誰でもその席に座れる。

卓に人が2人以上いる状態でこれが残っていると、**他人の手牌が見える**。
`ClientEvent` は席ごとに視界フィルタを通しているが、どの席として繋ぐかを
クライアントが自称できるなら、フィルタは意味を持たない。よってこの一枚は
「複数人で打てるようにする」と「席を名乗れなくする」が**同じ一つの仕事**である。

## 2. 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 席決め | 開始を押した瞬間にランダム | 実際の座決めと同じ。部屋主が必ず起家になる不公平が無い |
| 開始の合図 | 部屋主が押す。空席は CPU が埋める | 2人＋CPU2人でも、4人揃うまで待ってからでも選べる |
| 部屋コード | 6文字。`0O1I` を除いた32字の英数 | 口頭で伝えられる長さ。32^6 ≈ 10億 |
| 席の証明 | サーバ発行の32桁乱数トークン | 卓 id を知っているだけでは座れなくなる |
| 単独対局 | 部屋を作って即開始と同じ扱い | 入口を1本にする。`?table=` 経路と `const YOU: u8 = 0` は消す |
| 名前 | 待合にも対局画面にも出す | `MatchStart.players` に載る。protocol の変更は要らない |
| 部屋の寿命 | 最後の操作から30分 | 放置された待合を積み上げない |

## 3. 既にできていること —— protocol は変更しない

**これが今回の設計の土台である。** 調べた結果、凍結中の `crates/protocol` に
手を入れる必要は無い。

| 必要なもの | 現状 |
|---|---|
| 自分がどの席かをクライアントへ伝える | `ClientEvent::MatchStart { you: Seat }` が既にある。画面も `state.you = event.you` で受けている |
| 同卓者の名前 | `ClientEvent::MatchStart { players: [PlayerId; 4] }` が既にある（画面がまだ保持していないだけ） |
| 任意の席へ繋ぐ | `TableHandle::attach(seat, last_seq)` は席を選ばない |
| 席ごとの視界フィルタ | `project()` が既に席単位 |
| 切断中の進行 | 締切でツモ切りされ、卓は止まらない |

足りないのは**卓を立てる前に「誰がどの席か」を決める層**だけである。
`Occupant` は `spawn` の時点で固定されるので、部屋はその手前に立つ。

部屋のやり取りは **game protocol とは別系統の普通の HTTP JSON** とする。
凍結された型に部屋の概念を持ち込まないためであり、また部屋の形は
これから変わる（観戦・段位別マッチング）ので、凍結の外に置くのが正しい。

## 4. 部屋の状態

```
              作る                 開始（部屋主）
   （無）  ─────────→  待合  ─────────────────→  対局中  ──→  卓が閉じる ──→ 破棄
                      ↑  ↓ 入る（最大4人）                     ↑
                      └──┘                       30分無操作 ───┘
```

| 状態 | 意味 |
|---|---|
| `waiting` | 人が集まっている。卓はまだ無い |
| `playing` | 卓が立っている。`table_id` と席の割り当てを持つ |

**待合から人は抜けられない。** 離脱の API は作らない。閉じても
トークンが `localStorage` に残るので戻れる。誰も来なければ30分で消える。

**部屋主が消えたときに詰まないようにする。** 部屋主の最後の応答から
30秒が過ぎていれば、待合にいる誰でも開始を押せる。

## 5. HTTP API

すべて `/api/rooms` の下。要求も応答も JSON。
トークンは **`X-Mahjong-Token` ヘッダ**で送る。クエリ文字列に置くと
アクセスログや `Referer` に席の証明が残るからである。
WebSocket だけは例外でクエリに置く（ブラウザは WS 要求にヘッダを付けられない）。

### `POST /api/rooms`

部屋を作る。作った人が部屋主になり、そのまま入室する。

```json
要求: { "name": "まさ" }
応答: { "code": "K7QM2X", "token": "9f3c…（32桁）" }
```

### `POST /api/rooms/{code}/join`

入る。

```json
要求: { "name": "たろう" }
応答: { "token": "1a8e…" }
```

| 失敗 | 状態 | 本文 |
|---|---|---|
| コードが無い | 404 | `{ "error": "no_such_room" }` |
| 4人埋まっている | 409 | `{ "error": "room_full" }` |
| もう始まっている | 409 | `{ "error": "already_started" }` |

### `GET /api/rooms/{code}`

待合の様子。**1秒ごとに引く。** ヘッダのトークンで「まだ見ている」ことを
記録し、それが待合の「接続中」表示と、部屋主の生死判定の両方を兼ねる。

```json
{
  "state": "waiting",
  "you": { "name": "まさ", "host": true },
  "members": [
    { "name": "まさ", "host": true, "present": true },
    { "name": "たろう", "host": false, "present": false }
  ],
  "can_start": true
}
```

`state` が `"playing"` になったら、クライアントは WebSocket へ移る。
`present` は最後の応答から10秒以内かどうか。**席はここに出さない。**
開始まで決まらないからであり、決まった席は `MatchStart` が運ぶ。

### `POST /api/rooms/{code}/start`

卓を立てる。部屋主のみ（4節の例外を除く）。

```json
応答: { "state": "playing" }
```

このとき起きること。

1. `[0,1,2,3]` を OS 乱数でシャッフルする
2. 人を入室順にシャッフル後の席へ置く。`Occupant::Human(PlayerId(名前))`
3. 残りを `Occupant::Cpu` で埋める。名前は「CPU」
4. `spawn` して `Tables` に載せる。部屋は `playing` になり `table_id` と席割りを持つ

### `GET|POST` 以外・不明なトークン

トークンが部屋の誰とも一致しなければ 401 `{ "error": "bad_token" }`。

## 6. WebSocket

```
ws://…/ws?token=<32桁>&last_seq=<数>
```

`table=` は**廃止する**。トークンから部屋を引き、部屋から `table_id` と
席を引く。どちらかが無ければ接続を閉じる。`const YOU: u8 = 0` は消える。

トークンは席そのものなので、**同じトークンで繋ぎ直せば同じ席に戻る**。
既存の「同じ席への2本目の接続は1本目を置き換える」性質がそのまま効く。

## 7. 画面

### ロビー（`#/`）

3つだけ。

- **ひとりで打つ** —— 部屋を作って即座に開始する。CPU3人。今までと同じ体験
- **部屋を作る** —— 名前を入れて待合へ
- **部屋に入る** —— コードと名前を入れて待合へ

### 待合（`#/room/K7QM2X`）

- コードを大きく出す。押すとクリップボードへ入る
- 4つの枠。埋まっていれば名前、空いていれば「空き（CPU が入ります）」
- 部屋主にだけ「開始」。他の人には「部屋主を待っています」
- 1秒ごとに `GET`。`playing` になったら対局画面へ

### 対局画面

いまの盤面に**名前を出す**。`MatchStart.players` を `GameState` に保持し、
`席0 25000点` としていたところを `まさ 25000点` にする。自分の席には
「自分」の印がすでに付いている。

**名前は必ず `textContent` で入れる。** `innerHTML` に混ぜない。
名前は他人が入力した文字列であり、ここが唯一の流入口になる。

## 8. 名前の扱い

サーバが受け取った時点で正す。

- 前後の空白を落とす
- 制御文字を落とす
- 12文字を超えたら切る
- 空になったら「プレイヤー」

`PlayerId` は文字列なのでそのまま入る。**同名を拒否しない。**
席が違えば別人として扱えるので、拒否する理由が無い。

## 9. 掃除

- 卓が閉じた部屋は捨てる（`Tables::sweep` と同じ機会に）
- 最後の操作から30分を過ぎた `waiting` の部屋は捨てる
- 部屋の台帳は `Tables` と同じくインメモリ。プロセスが落ちれば消える

## 10. 試験

| 何を確かめるか | どこで |
|---|---|
| コードは重複しない。紛らわしい文字を含まない | server 単体 |
| 5人目は 409。開始後の入室も 409 | server 単体 |
| 開始で席がシャッフルされ、人が全員別の席に着く | server 単体 |
| 空席が CPU で埋まる。人2人なら CPU 2人 | server 単体 |
| 他人のトークンではその席に繋げない | server 単体 |
| トークン無しの WS は閉じる | server 単体 |
| 部屋主が10秒以上黙っても、30秒経つまでは他人が開始できない | server 単体 |
| 名前が12文字に切られ、制御文字が落ちる | server 単体 |
| 待合の描画、`playing` への遷移 | web 単体 |
| 名前が `textContent` で入る（`<script>` を名前にしても実行されない） | web 単体 |
| 2人が別の席で同時に打てる | server 結合 |

## 11. やらないこと

ここで作らないものを明記する。**後で「入っていると思っていた」と
食い違わないため。**

- アカウント・ログイン・段位（名前は毎回入力する）
- 牌譜の保存（`persistence.rs` は空のまま）
- 観戦
- 部屋の設定変更（東風・喰いタン等。金の間の既定のまま）
- ランダムマッチング（コードを知っている人としか打てない）
- 途中離脱の明示的な扱い（締切でツモ切りされる既存の挙動のまま）
- 対局中のチャット
